# dsh-attendance

DSH 考勤插件，通过日期选项卡和早上、下午、晚上三张时段卡片记录工时，自动计算每日与每周时长，并保留历史记录。当前版本为 **0.4.2**，侧栏入口为“考勤”，支持中英文及 DSH 主题。

## 功能

- 按周展示七个日期，点击日期编辑当天的上班、下班时间；支持上一周、下一周、返回本周、按日期查询和有记录的周列表。
- 六个时间点可独立设为固定预设；其余时间点允许手动填写。
- 自动汇总完整有效的时段，显示所选日期概览和实际本周的进度；每周目标默认 **40 小时**，可单独调整。
- 0.4.2 为手填时间块、时间编辑框和预设输入框增加垃圾桶按钮。
- 日期选项卡支持左右方向键、Home、End；窄屏日期区可横向滚动，时段卡片纵向排列。

## 安装与更新

这是 DSH 插件，需要在 DSH 中运行，不能作为独立网页直接打开。

```sh
git clone https://github.com/lxc0205/dsh-attendance.git
cd dsh-attendance
```

在 DSH 的“插件”页面添加克隆目录的**绝对路径**，例如 Windows 的 `C:/Projects/dsh-attendance` 或 Linux/macOS 的 `/opt/projects/dsh-attendance`，然后启用插件并打开侧栏“考勤”。请替换为实际克隆位置。

更新时在克隆目录运行 `git pull`，再重启 DSH 并重新打开“考勤”，以加载更新后的客户端代码。安装和更新通过 DSH 插件管理界面或官方插件命令完成。

DSH 0.2.1-rc.5 是当前核对插件接口所用的基线，尚未确定支持的最低 DSH 版本。插件使用 DSH 提供的 React 18、Module Loader、slots 和 locale 服务，无额外 npm 依赖，也无需构建步骤。

## 记录考勤

1. 选择日期，点击可编辑的时间块填写时间，再点“保存时间”；“取消”或 Escape 可退出编辑。
2. 若使用固定预设，未记录日期只展示预览。点击“记录当天考勤”，或保存一个手填时间点，才建立记录并参与统计。
3. 手填时间块右侧的垃圾桶会**立即清空已保存的该时间点**并重新计算时长；空值时不可用，固定时间块不显示删除按钮。
4. 时间编辑框、固定预设配置中的垃圾桶只清空当前草稿，仍须点击相应保存按钮才生效。

仅填写一个端点的时段保留为待补状态，不计时长。已建立的日期即使清空了全部手填时间，仍保留在历史目录。

## 固定时间预设与历史保护

打开“固定时间预设”，可分别配置早上上班、早上下班、下午上班、下午下班、晚上上班、晚上下班六个时间点。每点独立：有值即固定锁定，留空则允许手填。例如只固定早上上班为 `09:00`，早上下班仍可手填。

保存会校验时间格式、完整时段的起止顺序及重叠，允许只设置时段的一个端点。

- 新建记录时保存预设快照，固定字段不能通过时间块手动修改。
- “保存并同步今天”以 **Asia/Shanghai 的真实今天**为目标，与当前查看日期无关。今天已有记录时，非空预设覆盖对应时间点并锁定；预设留空则保留该点原值并开放手填。
- 今天尚无记录时，只保存配置、更新预览，**不会自动记录出勤**。
- 过去的记录保留原快照与计算结果；保存预设也不会修改已经保存的未来记录。
- 0.3.0 历史记录继续保留；今天的旧版记录可在同步预设时升级。0.2.0 通用时段设置可作为首次预设的默认值读取，不会被改写或自动转成出勤记录。
- 从 0.4.0 升级时，打开配置并点击一次“保存并同步今天”，即可将预设应用到今天已有的记录，无须先修改预设值。

如果其他标签页在创建记录期间修改了预设或当天记录，插件会提示刷新后核对。若提示预设已保存但今天同步失败，再次保存可重试同步。

## 计算与日期规则

只累计完整、有效且不重叠的时段。结束时间必须晚于开始时间，暂不支持跨午夜。相互重叠的时段会提示错误，并全部排除出累计；相邻时段共用一个端点不算重叠。

日期按 **Asia/Shanghai（上海时区）**计算，每周从周一到周日。本周进度始终统计真实本周的已保存时长，浏览历史不会改变本周进度。周目标按周保存，允许大于 0 且不超过 168 小时；超过目标后仍显示实际时长和百分比。

页面每 30 秒检查日期，在窗口聚焦或恢复可见时也会检查。保存预设和提交目标时再次核对日期或周次，避免跨日、跨周时写错记录。保存失败的草稿不计入统计。

## 数据保存与使用限制

记录与周目标保存在浏览器 **localStorage** 中。多标签页使用 Web Locks 协调同一天的写入，并在变更后通知其他标签页刷新；存储失败时保留编辑草稿供重试，读取损坏的日期时禁止编辑，以保护原始记录。

- 数据按浏览器与 **origin（协议、主机名、端口）**隔离，不按 DSH profile 隔离。`localhost` 和 `127.0.0.1`、不同端口或不同浏览器均可能对应不同存储。
- 更换设备、浏览器、网页地址或迁移插件目录不会自动迁移数据；仅移动插件代码不能保证记录继续可见。清除浏览器站点数据会删除记录。
- 写入需要浏览器支持 Web Locks，且页面位于可信来源（安全上下文）。HTTPS 或通常被浏览器视为可信的本机 `localhost` / `127.0.0.1` 可满足来源要求；普通远程 HTTP 地址可能无法使用。
- **Host 共享存储尚未实现**，目前没有跨设备同步、备份导入或导出功能。

## 开发与验证

开发环境要求 **Node.js >= 22**，当前仅在 **Node.js 24.21** 上实测。无需安装额外 npm 依赖，在项目根目录执行：

```sh
npm test
npm run check
```

`npm test` 运行 57 项模型与包资源测试，覆盖时长计算、周日历、预设锁定、手动与固定混合、旧版兼容、历史快照、存储失败及历史查询。测试入口为 [`verify-attendance.cjs`](./verify-attendance.cjs)，按脚本自身所在目录定位项目。`npm run check` 执行语法检查。

已配置 GitHub Actions，覆盖 Ubuntu、Windows 与 Node.js 22 / 24 的组合；实际通过情况以仓库运行记录为准。模型测试不模拟 React 或 DOM；尚未完成浏览器页面验证，布局、实际交互、深浅主题及真实浏览器中的 Web Locks 行为仍待核对。
